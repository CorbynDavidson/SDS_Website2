# SDS primary-domain migration

Production origin: **https://www.sds-solicitors.com**. This release prepares the code and publishes the review build. It does not change SDS DNS or the current primary-domain hosting.

## Implemented and verified

- All 296 captured routes retain original page wording, titles and descriptions, apart from the previously requested Reviews title correction and the owner's screenshot form replacement on `/housing-disrepair-enquiries/`. That page uses the original homepage callback wording and fields; its non-form content and SEO remain unchanged. All 248 URLs from the current live sitemap have a 200 route or a single 301 followed by a 200 route.
- Canonical, Open Graph URL/image, Twitter URL/image and public internal navigation hrefs use fully qualified production URLs. Original XPath and other non-URL schema values are preserved. Review-host navigation stays in the review build while retaining production hrefs and canonicals. Stylesheets, icons and other local resource links use root-relative URLs so the review build loads its own assets before DNS cutover.
- The production XML sitemap contains 243 unique, self-canonical, indexable URLs: 242 original SDS URLs plus `/faqs/`. The six original noindex utility pages remain available but are omitted, as are aliases and page-one query duplicates; page-two listings remain available. `public/sitemap.xml` and the Worker response use the same generated bytes.
- 294 exact permanent path rules are executed at the Cloudflare Worker edge. Queries and campaign parameters are retained; page-one pagination is removed. HTTP/apex/path changes are combined into a single 301. Exact duplicate captured content redirects to its original canonical. Filtered listings with different content retain their route and original canonical. The eight selected design alternatives also redirect on review hosts, staying on the current origin.
- All 297 retained public templates have global `LegalService` JSON-LD for Sheldon Davidson Solicitors, `0161 796 3000`, and the requested Whitefield/Manchester address. SRA 519502 is encoded with valid `identifier` / `PropertyValue` syntax (`propertyID: sraNumber`); Schema.org has no native `sraNumber` property. Existing disrepair `Service` schema is preserved and links to the firm; missing service nodes are added.
- Public primary-domain pages are indexable in production mode. Review hosts are noindex independently of release mode and have `Disallow: /`. Primary robots permits public pages and blocks administration, API, editor, staging/preview/build routes and edit queries. Administration still requires the existing owner authentication. Unknown URLs remain honest 404s; verified retired 410s remain 410s.
- Terms of Business remains `/about-us/terms-business/`, with exact live wording, headings, lists and tables checked on 6 October 2026. It has the approved version-53 page presentation and shared header/footer.
- Claim buttons keep the existing `/housing-disrepair-enquiries/` destination, which now displays the five-field homepage callback form in the single-column layout selected by the owner. Its original callback options and consent remain, and submissions store the retained enquiry URL through the tested existing handler. Other enquiry pages keep their original fields, options, consent, uploads and five-step journeys. All original backend schemas remain available. Repeated CMS form IDs are consolidated; wrapper elements no longer receive input borders. The approved version-53 site design remains intact.

## Primary-domain cutover

1. Complete the operational checks in `LAUNCH_CHECKLIST.md` and retain the current hosting/DNS rollback state. Source code readiness does not sign off CRM, consent, backups or device QA.
2. Use the same Sites project from `.openai/hosting.json`, preserving `DB`, `ASSET_STORAGE`, owner authentication and existing secret values. Keep the public audience unchanged.
3. Set only `RELEASE_MODE=production` in the Sites runtime variables, then deploy the tested saved version to apply that revision. With the current review setting, primary-domain pages are also noindex; this must be changed before primary-domain cutover. Every review hostname remains noindex even in production mode.
4. Attach both `www.sds-solicitors.com` and `sds-solicitors.com` to the selected host and obtain its actual DNS/validation records. The Worker normalises apex and HTTP requests to HTTPS/www. Preserve all email records. No example IP address or guessed DNS target is supplied here.
5. After switching only the website records, verify HTTPS, production robots, the sitemap, representative canonical/schema URLs, redirects, media and real form/operational follow-up. Submit the sitemap in the existing Search Console property and monitor errors, enquiries, crawl coverage and traffic.

## Validation and source files

`npm run check` builds the current design, compares original copy and shared components with the one recorded screenshot-form exception, checks production routes/SEO/schema/crawl behaviour, and runs all fourteen persistence/security tests. GitHub CI uses the same command. `npm run validate:production` repeats only the production audit on an existing build.

Relevant files: `scripts/lib/production-seo.mjs`, `worker/production-routing.mjs`, `config/site.json`, `config/legacy-routing.json`, `src/current-content-layout.css`, and the generated reports in `docs/migration/`.

The baseline renderer's fingerprint changes only because its domain references changed. Its original visual CSS/components remain intact. The version-54 SEO refactor had incorrectly pointed `brand.css` and `service.css` at the old primary-domain host; version 55 restored the layout file but retained that loading defect. The correction keeps resource links on the current build and verifies both served stylesheet hashes against version 53 on review and production hosts. Immutable source captures, SEO baselines and historical deployment records are deliberately retained; local development ports remain development tooling and never appear in public page output. A browser/device review is still pending because the required browser-control skill was unavailable in this execution environment.
