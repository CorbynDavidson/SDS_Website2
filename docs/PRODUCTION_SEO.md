# SDS primary-domain migration

Production origin: **https://www.sds-solicitors.com**. This release prepares the code and publishes the review build. It does not change SDS DNS or the current primary-domain hosting.

## Implemented and verified

- All 296 captured routes retain original wording, titles and descriptions, apart from the previously requested Reviews title correction. All 248 URLs from the current live sitemap have a 200 route or a single 301 followed by a 200 route.
- Canonical, Open Graph URL/image, Twitter URL/image and public internal hrefs use fully qualified production URLs. Original XPath and other non-URL schema values are preserved. Review-host navigation stays in the review build while retaining production hrefs and canonicals.
- The production XML sitemap contains 251 unique, self-canonical, indexable URLs. Aliases and page-one query duplicates are omitted; page-two listings remain available. `public/sitemap.xml` and the Worker response use the same generated bytes.
- 286 exact permanent path rules are executed at the Cloudflare Worker edge. Queries and campaign parameters are retained; page-one pagination is removed. HTTP/apex/path changes are combined into a single 301. Exact duplicate captured content redirects to its original canonical. Filtered listings with different content retain their route and original canonical.
- All 305 public templates have global `LegalService` JSON-LD for Sheldon Davidson Solicitors, `0161 796 3000`, and the requested Whitefield/Manchester address. SRA 519502 is encoded with valid `identifier` / `PropertyValue` syntax (`propertyID: sraNumber`); Schema.org has no native `sraNumber` property. Existing disrepair `Service` schema is preserved and links to the firm; missing service nodes are added.
- Public primary-domain pages are indexable in production mode. Review hosts are noindex independently of release mode and have `Disallow: /`. Primary robots permits public pages and blocks administration, API, editor, staging/preview/build routes and edit queries. Administration still requires the existing owner authentication. Unknown URLs remain honest 404s; verified retired 410s remain 410s.
- Terms of Business remains `/about-us/terms-business/`, with exact live wording, headings, lists and tables checked on 6 October 2026. It has the shared header/footer and readable rounded panels.
- Claim buttons keep the existing `/housing-disrepair-enquiries/` destination. Enquiry pages keep every original field, option, consent statement, upload control and five-step journey. Repeated CMS form IDs are consolidated; wrapper elements no longer receive input borders. The shared layout uses 1240px/header-aligned rounded light-grey panels and responsive form cards.

## Historic non-housing URLs

The current live SDS website states that the firm no longer accepts new Personal Injury, Serious Injury or Medical Negligence claims. These service pages are absent from its current 248-URL sitemap. The new code preserves measured live routing instead of inventing replacement service copy.

| Legacy paths | New response |
|---|---|
| `/medical-negligence/`, `/clinical-negligence/`, `/medical-negligence-claims` and descendants | Single 301 to the existing Discontinued Legal Services page |
| `/road-traffic-accidents/`, `/road-traffic-accident-claims/`, `/road-bike-accident-claims` and descendants | Single 301 to the same existing notice |
| `/accidents-work-claims` and descendants | Single 301 to the same existing notice |
| `/personal-injury` and `/personal-injury/` | Existing live 301 to `/` preserved |
| `/serious-injury/` and the verified former child-injury page | 301 to the existing notice; the old serious-injury alias had led to a 404 |
| Verified old electrocution page and two retired news/case-study URLs | Existing 410 responses preserved |
| Verified old leg-injury calculator URL | Existing calculator destination preserved |

The exact rules and current response evidence are in `config/legacy-routing.json`. Service-family wildcard redirects were checked against live descendants, including an unlisted path, before implementation. Exact 410 exceptions are kept outside those families. The generated captured-page map is `migration/production-url-map.csv`.

**The complete 25-year historic inventory is not yet available.** Compare Search Console, backlink exports, old server redirect configuration and request logs before cutover. Public sitemap coverage alone cannot establish that no older backlink URL is missing. Add discovered rules to the routing config and rerun validation.

## Primary-domain cutover

1. Complete the operational checks in `LAUNCH_CHECKLIST.md` and retain the current hosting/DNS rollback state. Source code readiness does not sign off CRM, consent, backups or device QA.
2. Use the same Sites project from `.openai/hosting.json`, preserving `DB`, `ASSET_STORAGE`, owner authentication and existing secret values. Keep the public audience unchanged.
3. Set only `RELEASE_MODE=production` in the Sites runtime variables, then deploy the tested saved version to apply that revision. With the current review setting, primary-domain pages are also noindex; this must be changed before primary-domain cutover. Every review hostname remains noindex even in production mode.
4. Attach both `www.sds-solicitors.com` and `sds-solicitors.com` to the selected host and obtain its actual DNS/validation records. The Worker normalises apex and HTTP requests to HTTPS/www. Preserve all email records. No example IP address or guessed DNS target is supplied here.
5. After switching only the website records, verify HTTPS, production robots, the sitemap, representative canonical/schema URLs, redirects, media and real form/operational follow-up. Submit the sitemap in the existing Search Console property and monitor errors, enquiries, crawl coverage and traffic.

## Validation and source files

`npm run check` builds the current design, compares original copy and shared components, checks production routes/SEO/schema/crawl behaviour, and runs all thirteen persistence/security tests. GitHub CI uses the same command. `npm run validate:production` repeats only the production audit on an existing build.

Relevant files: `scripts/lib/production-seo.mjs`, `worker/production-routing.mjs`, `config/site.json`, `config/legacy-routing.json`, `src/current-content-layout.css`, and the generated reports in `docs/migration/`.

The baseline renderer's fingerprint changes only because its domain references changed. Its original visual CSS/components remain intact. Immutable source captures, SEO baselines and historical deployment records are deliberately retained; local development ports remain development tooling and never appear in public page output. A browser/device review is still pending because the required browser-control skill was unavailable in this execution environment.
